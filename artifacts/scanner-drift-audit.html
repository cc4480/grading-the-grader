What the 111 commits already fixed

Listed because the first draft of this report claimed them, and because the fixes validate the recommendation at the end: four of the six were closed by extracting a shared module and deleting the local copies.

Closed

Domain verification now exists, and matches the published instructions

lib/domainVerify.ts · lib/activeProbeGate.ts · routes/domainVerification.ts · pages/domains.tsx

The ownership gate secscan.info advertises is implemented, fails closed, and uses exactly the names the site publishes — _secscan-challenge.<domain> and /.well-known/secscan-verification.txt. The /domains page exists. My headline finding is void.

Closed

The 12 advertised-but-absent checks were implemented

lib/mailTls.ts · lib/structuredData.ts

Both modules now exist, with the STARTTLS, JSON-LD, Open Graph and Twitter Card detections the coverage page describes. mailTls.ts reports “Mail Server Does Not Offer STARTTLS”, “…TLS Certificate Expired” and “…Expiring Soon”.

Closed

Both open redirects, fixed by the right move

lib/safeRedirect.ts — imported by routes/auth.ts and routes/googleAuth.ts

A new shared helper resolves returnTo through the same URL parser the browser uses and compares origins, instead of guessing at prefixes. Its docstring names both bypasses I found — the bare //evil.com, and the /\evil.com form the parser normalises into it.

Closed

The doubled SSRF check, and the message it hid

routes/scans.ts:167

Now a single checkScanTarget call, with the plain-English error restored. The commit comment states the diagnosis exactly: the first call returned with the guard's terse internal reason, so the readable message below was unreachable.

Closed

Anonymous identities can no longer store an API key

routes/settings.ts — deleted

The per-user DeepSeek key endpoint is gone, which removes the inconsistency with POST /scans's refusal to store credentials for the same identities.

Closed

Scan limits are now per-user, and authentication runs first

lib/rateLimit.ts — keyFrom, scanNetworkRateLimitRules

Not something I flagged, but it fixes a real hole in the code I reviewed: the limiter used to run before authentication, so an anonymous caller could spend a signed-in user's scan allowance. Now bucketed per user with a per-network ceiling above it.

VibeScan-Enterprise-Build · a664c13

Still open

Two services from one repo — seclayer (web tier) and secscan (scanner), per docker-compose.yml. The shared libraries here are good; the routes still keep reaching around them.

Billing

Stripe credit grants still have no idempotency

artifacts/api-server/src/routes/stripe.ts:123

.set({ balance: existing.balance + creditsToAdd })

Read-then-write, outside a transaction, with no event-id dedupe and no unique constraint. Stripe redelivers on any non-2xx — and this handler returns 500 on a processing error, guaranteeing the retry. A duplicate delivery double-credits; two concurrent deliveries lose one grant entirely.

Sibling comparison: seclayer.io2026 guards the same handler with hasTransactionForSession(). VibeScan has no equivalent.

Evidence

OOB callback source IPs are attacker-forgeable

artifacts/api-server/src/routes/oob.ts:20

function clientIp(req) { return String(req.headers["x-forwarded-for"] ?? …).split(",")[0].trim(); }

A local helper that takes the leftmost X-Forwarded-For entry — precisely the read that lib/clientIp.ts exists to prevent, and whose docstring opens by naming it as the way to get this wrong. The value is stored as sourceIp, the evidence that proves a blind-SSRF callback fired, so a finding's proof can be forged by whoever triggers it.

Sibling comparison: seclayer.io2026's equivalent route uses req.ip, which honours the configured proxy trust.

SSRF

The rebinding guard resolves a different address than it connects to

artifacts/api-server/src/lib/http.ts:364 → :384

The per-hop comment claims “the last word has to belong to the code that is about to open the socket.” It does not: checkUrlSafe() resolves through dns.lookup with a 30-second positive cache, and fetch() twenty lines later resolves independently. There is no custom dispatcher, agent or lookup — nothing pins the vetted address to the connection.

Sibling comparison: seclayer.io2026/server/ssrf.ts installs a validating lookup inside the undici connect path, and documents exactly why — “the validated lookup IS the connect lookup — there is no second, unchecked resolution.” That is the fix; it is already written, in-house.

Boot

TRUST_PROXY=true crashes the server at startup

artifacts/api-server/src/app.ts:104–107

$ node -e "app.set('trust proxy', 'true')" # express@5.2.1 TypeError: invalid IP address: true

configureTrustProxy() parses true/false/hop counts/CIDR lists correctly — then a second block sixteen lines later re-reads the same env var and overwrites the result with Number.isNaN(hops) ? trustProxy : hops, handing Express the raw string. Verified against the installed Express.

Shipped configs all use numeric values, so this is latent — but lib/clientIp.ts documents true/false as supported, and its value === true safety warning is now unreachable.

Billing

Late Stripe events can flip a finished scan to failed

artifacts/api-server/src/routes/stripe.ts:146–166

checkout.session.expired and payment_intent.payment_failed both set status: "failed" unconditionally, with no guard on the current state. A delayed event overwrites complete, discarding a scan the user already has.

Quota

A malformed limit env var silently disables the daily cap

artifacts/api-server/src/routes/scans.ts:29–30

const DAILY_MAX_ANON = Number(process.env["SCAN_DAILY_LIMIT_ANON"] ?? 10); // "50/day" → NaN → (count >= NaN) is always false

The comment above it calls this quota “what actually bounds cost.” The fix already exists in the file it imports from: lib/rateLimit.ts has parsePositiveInt(), written for this exact hazard, and the new network-limit rules added on master use it.

Email

Reset and verification links break when APP_ORIGIN is unset

artifacts/api-server/src/routes/account.ts:386

// account.ts, local return (process.env["APP_ORIGIN"] ?? "").replace(/\/+$/, ""); // lib/appOrigin.ts, shared (process.env.APP_ORIGIN ?? "https://secscan.us").replace(/\/$/, "");

The local copy falls back to an empty string, so the mail body carries /reset-password?token=… — a relative URL, dead in an inbox. Every other email link in the codebase imports the shared constant and works.

Enum

Registration leaks which emails have accounts — twice

artifacts/api-server/src/routes/account.ts:141, login handler

Login is two-factor on master now, and its password step is still carefully uniform. POST /account/register nonetheless answers 409 "An account with that email already exists".

A second, quieter leak sits in the password step itself: !row?.passwordHash returns before any hashing work, while a real account runs a 64 MB scrypt. The response-time gap distinguishes the two cases regardless of the uniform message.

Growth

Nothing ever purges spent auth tokens

artifacts/api-server/src/lib/authTokens.ts

purgeStaleTokens() is written, documented as “Housekeeping”, and still has zero callers — no scheduler, no worker, no route. The auth_tokens table grows without bound.

Dead

The payments subsystem is still wired at only one end

artifacts/api-server/src/routes/credits.ts:20 · routes/stripe.ts:123

balance is read in one place and incremented in one place. Nothing decrements it — POST /scans never consults or debits credits. There is no checkout.sessions.create anywhere, so no route can sell anything. Scans are bounded by the daily quota instead, which makes the whole credit ledger inert.

Dead

Two unreferenced symbols on the auth path

routes/auth.ts:134 · lib/authTokens.ts

In the OIDC callback, const callbackUrl = getCallbackUrl(req) is computed and never read — the grant uses currentUrl instead. (The identical line at :84 is live; only the callback copy is dead.) tokensEqual() is exported with a comment explaining it exists “so callers are not tempted to use ===”, and has no callers.

Dup

Three hand-rolled rate limiters remain

routes/account.ts · routes/auth.ts · routes/googleAuth.ts

Each keeps its own Map that is never pruned — one entry per IP, forever — and each pushes the timestamp before comparing, so a caller who keeps hammering extends their own block. lib/rateLimit.ts sweeps idle buckets and documents not counting blocked requests, and master just taught it a keyFrom hook. These three never adopted it.

secscan-info · 631d519

The reference library

Small, careful, and unusually well reasoned about its own CSP — the _headers policy genuinely ships no unsafe-inline anywhere. With the engine caught up, the remaining drift is arithmetic.

Count

The signature total is still off by one — now in the other direction

src/data/coverage.ts — TOTAL_SIGNATURES, signatures[]

claimed actual (a664c13) SENSITIVE_PATHS 78 78 ✓ SECRET_PATTERNS 33 34 ✗ SERVICES 19 19 ✓ PATH_PROBES 8 8 ✓ TOTAL_SIGNATURES 138 139 ✗

At my first reading the table held 32 and the page claimed 33. Patterns were added since; the page still claims 33. The number has now been wrong in both directions without the page changing — which is the argument for deriving it at build time rather than transcribing it.

Contra

The file contradicts itself, and the true half has swapped

src/data/coverage.ts — TOTAL_CHECKS vs gates[0]

One line reads “Every scan runs every check. The tier was retired.” Forty lines later, domain verification “unlocks all active probing” and “without it only passive checks run.” When I first read this, the engine agreed with the first statement. Now that activeProbeGate.ts ships and fails closed, the engine agrees with the second — so the contradiction has not been resolved, it has inverted.

Spec

security.txt is missing the required Expires field

public/.well-known/security.txt

RFC 9116 §2.5.5 makes Expires mandatory; parsers treat a file without it as invalid. The file carries only Contact, Preferred-Languages and Canonical.

CI

Both build assertions pass when they match no files

.github/workflows/deploy.yml — “Assert no inline script or style”

count=$(cat dist/*.html dist/**/*.html 2>/dev/null \ | grep -o 'style="\|<script' | wc -l)

If the glob matches nothing — output path renamed, build layout changed — the pipeline yields an empty stream, count is 0, and the check reports success. The canonical-URL assertion below it fails open the same way. Both guard a CSP that has no unsafe-inline to fall back on.

seclayer.io2026 · 79a0678

The standalone app

Unchanged since the first pass, and the stronger of the two engines: near-total test coverage and the correct connect-time SSRF pin. Both real findings are in one place — the credit ledger, where the file's own careful locking is applied unevenly.

Money

The shared credit helper is the one path that doesn't lock the row

server/pg/pgDb.ts:117 — _addCreditsWithin

:117 SELECT * FROM users WHERE id = ? ← no lock :285 SELECT * FROM users WHERE id = ? FOR UPDATE ← deductCredits :587 SELECT * FROM users WHERE id = ? FOR UPDATE ← api-key path

deductCredits pre-locks before delegating, so it is safe. The callers that don't — the Stripe grant via addCredits(), and the refund paths in recoverStuckScans / recoverStuckNmapScans — read an unlocked balance and write back a computed value. Under Postgres's default READ COMMITTED that is a lost update: a refund racing a debit can hand back a credit the user already spent.

Money

The duplicate-purchase guard has nothing behind it

server.ts:113 · server/pg/schema.sql — transactions

if (completion && !(await db.hasTransactionForSession(completion.sessionId))) CREATE TABLE transactions ( … stripeSessionId text … ); CREATE INDEX idx_tx_user ON transactions(userId); -- the only index

stripeSessionId carries no unique constraint, and the check sits outside the transaction that writes the row. Two concurrent deliveries of the same checkout.session.completed both see no prior transaction and both grant. A unique index on that column turns the race into a constraint violation the handler can swallow.

Dup

The mailbox rate limiter re-implements the function it imports

server/routes/auth.ts — requestLinkEmailLimiter.keyFrom

normalizeLoginEmail is imported at the top of the file; the limiter inlines raw.toLowerCase().trim() instead. The two agree today, exactly. They are also the two halves of the guarantee the comment above them makes — five codes an hour against a million-value keyspace — so if the shared normaliser ever canonicalises further, the per-mailbox cap stops matching the lookup key and the bound quietly stops holding.

The through-line

Every shared module has a worse copy pasted next to it

Seven of the open findings are the same defect — and the fixes prove the remedy

These codebases are unusually well commented, and the shared libraries' reasoning is right. The failures are almost all local re-implementations written without it. The strongest evidence is what master already fixed: both open redirects closed the moment someone extracted lib/safeRedirect.ts and deleted the two local copies. The same move is available for each of these.

  • lib/rateLimit.ts prunes idle buckets and documents not counting blocked requests. auth.ts, googleAuth.ts and account.ts each hand-roll a limiter that does neither.
  • lib/clientIp.ts opens by naming leftmost-XFF as the way to get this wrong. routes/oob.ts does exactly that, on the path that records evidence.
  • lib/appOrigin.ts exists because origins used to be hardcoded. routes/account.ts declares a local appOrigin() that drops the fallback.
  • lib/rateLimit.ts has parsePositiveInt(), and master's new network rules use it. routes/scans.ts still uses bare Number() for the quota that bounds cost.
  • configureTrustProxy() handles every documented value. app.ts re-parses the same variable sixteen lines later and overwrites it.
  • seclayer.io2026/server/ssrf.ts pins the connect-time lookup. VibeScan's http.ts checks, then lets fetch re-resolve.
  • seclayer's _addCreditsWithin is the one credit path that skips the FOR UPDATE its siblings take.
Method, and what this review covered

All three clones were stale at the start. secscan-info was cloned fresh; seclayer was 87 commits behind; VibeScan was 52 behind origin/main — and origin/main was itself 111 commits behind origin/master, the actual default branch, which the clone's stale origin/HEAD had been pointing away from. All three are now level with their remotes, working trees clean, no local-only commits anywhere.
